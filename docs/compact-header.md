# Compact header

Refs #163. At widths up to 900px, the header uses one measured 61px row: brand, labelled active-page drawer launcher and a directly visible quiz-update bell. Avatar/account/sign-in/loading, Quiz Bank, My quizzes, Donate, theme and VN/EN live inside the modal left drawer. Wider layouts retain their original direct controls and left/right alignment.

The drawer uses existing Ant Design components/tokens and native labelled controls with 44px targets. It is at most 320px wide, leaving at least 48px for mask access, and scrolls within the viewport. Close/mask/Escape return focus to the launcher; Tab stays inside. Desktop resize removes the drawer, restores brand focus and releases background scroll lock. The portal does not contribute to App.jsx's observed header height.

AccountMenu owns the shared actions and feature flags. Its compact avatar/name button expands an inline Menu; inner Escape closes that menu first. The avatar names the account, so its inline menu omits the redundant disabled name row. Long names truncate visually with their full accessible name/title. Account dialogs and guarded navigation wait for drawer dismissal/focus restoration; cancellation returns to the persistent launcher. Existing account-scoped drafts, checkpoints, auth policy and rollout flags are unchanged.

QuizUpdateNotifications retains its original standalone header dropdown, public access, unread/read-state hook, bounded scrollable panel and Escape/focus return to the bell. Opening the account drawer alone does not mark updates as read. Refresh keeps its existing owners and behavior. The temporary inline notification variant was removed after the owner selected the direct header bell.

UI/UX Pro Max guidance was applied through the bundled Python search and pinned local references. Earlier queries included `compact navigation focus menu` (ux), `responsive event cleanup` (React), `modal focus return` (ux) and `drawer nested navigation focus` (ux): keyboard navigation, focus appearance/return, sticky geometry and subscription cleanup were relevant. The final `notification visibility navigation` query included an irrelevant password result, which was discarded; `notification feedback` was also not specific enough. For notification placement/access, the local quick reference's icon-context, keyboard-nav, contextual-live-badge-updates and touch-target guidance was used as an explicit fallback. Existing labels/badge semantics and measured header spacing were preserved. No new framework or accessibility-conformance claim.
