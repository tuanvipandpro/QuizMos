## Build-time activation and rollback

The frontend workflow forwards the public repository Actions variable `VITE_EXAM_HISTORY_ENABLED` to the verified build, defaulting to `false` when unset. Only the exact value `true` enables capture/navigation; `false`, an empty value or any other spelling keeps it disabled. This is a build-time switch, so changing the variable requires a new reviewed frontend release; it does not change an already-published bundle. Local development uses the same variable from an ignored environment file, with `.env.example` retaining the disabled default.

Production Rules and both field exemptions were verified after owner publication on 10 November 2026; see [the acceptance checkpoint](https://github.com/tuanvipandpro/QuizMos/issues/80#issuecomment-6772934140). Before activation, review that compatible policy is still current and authorize designated-account archive/reload/review/delete acceptance. This wiring change does not set the repository variable or establish History production acceptance. Follow [the Git process](git-process.md) and existing frontend publication pipeline for release.

To stop new capture and hide History navigation, set the public variable to `false` (or remove it) and publish a reviewed frontend build. Preserve existing private archives and compatible Rules. Users with an older enabled bundle may remain active until reloading; the flag is not a server-side revocation control. Never delete user history or broaden access as rollback.

## Limits and identity

Named defaults live in `src/data/examHistoryLimits.js`: 50 retained attempts/account, 20 summaries per query/page, 100 questions/snapshot, a conservative 750 KiB serialized snapshot envelope and a payload UTF-8 budget with 4 KiB metadata headroom. At capacity the user explicitly deletes an older archive; no silent eviction occurs.

New exams receive a secure UUID, start time, grading-policy version, source identity, owner and capture eligibility. UUID creation supports native randomUUID or secure getRandomValues on HTTP LAN previews. Content fingerprints preserve SHA-256 across native Web Crypto and a tested UTF-8 fallback without a new dependency. Question source fingerprints reuse the existing guide contract through a shared pure utility.

Local draft signatures use `v2:` canonical object-key ordering while retaining all array order. Firestore map serialization therefore does not recreate an unchanged exam. Unchanged legacy raw signatures migrate only their signature metadata; reordered legacy cloud drafts additionally require the current owner/slot/instance/contentVersion boundary and compatible saved Exam content. Legacy Practice drafts rely on that server-enforced immutable version because they contain no question snapshot. Mismatching bank or v2 signatures fail closed. Migration preserves the stored shuffle, answers, flags, deadline, attempt ID and capture eligibility; it does not recover a draft already overwritten by an earlier reset. Retain the v2 reader during rollback: a legacy-only reader can invalidate migrated drafts. History can be disabled through its reviewed flag flow while keeping this compatibility correction. [#150](https://github.com/tuanvipandpro/QuizMos/issues/150) tracks this correction.

Resume keeps the same questions, option insertion order, answers, mode, absolute deadline and attempt ID. A pre-history active draft receives additive metadata and unknown start/duration; a pre-history completed draft is not backfilled. Completed drafts from disabled history, guests and unsaved local uploads do not start uploading after enablement. Manual submit, timer expiry and late answers use one terminal transform; expiry ends at the existing absolute deadline.

## Schema version 1

All paths are private children of `users/{uid}`. The parent profile permission does not grant descendant access.

| Path                               | Stored contract                                                                                                                                                                                                                |
| ---------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `examAttempts/{attemptId}`         | Immutable summary: schema/attempt ID, source, start/end/elapsed, Standard/Learning mode, grading version/end reason, question/correct/incorrect/unanswered counts, original pass result, payload hash and server creation time |
| `examAttemptSnapshots/{attemptId}` | Immutable schema/attempt ID, payload SHA-256, canonical JSON payload string and server creation time; fetched only for review                                                                                                  |
| `examHistoryState/quota`           | Count/revision plus the attempt/operation and server time coupled to each create/delete                                                                                                                                        |
| `examAttemptReceipts/{attemptId}`  | Saved fingerprint/creation state; after deletion, only deleted state and timestamps remain                                                                                                                                     |

The source is `{kind,id,title,fingerprint,slotId,instanceId,contentVersion}`. Bank IDs are canonical (including `aws-ace` → Google ACE). Private grouping uses the stable instance UUID, with the captured slot/contentVersion; a reused slot cannot own the old archive.

The payload repeats summary context and stores allowlisted questions, selected answers and frozen per-question complete/correct outcomes. MC selections are archived as arrays; Yes/No/dropdown selections are mappings. Only question/rendering/correct-answer fields are retained; arbitrary source metadata, explanations, generated AI output and credentials are excluded. Option insertion order is preserved because it is the exam's displayed order. Selected/correct object maps normalize irrelevant property order.

Capture invokes the shared scorer on the original terminal answers, then normalizes their storage shape. In particular, the current live scorer accepts legacy single-choice strings; the archive's array representation does not regrade those answers. `quizmos-score-v1` retains strict **more than 80%** passing and the existing complete/incorrect/unanswered distinctions. Replay validates schema, source/hash and structural/count consistency, and displays stored outcomes/version rather than invoking today's scorer. Unknown start time stays unavailable; it is not inferred from an old deadline.

## Atomic lifecycle and deletion

Create writes summary, snapshot, quota and receipt together in an online transaction. The same attempt/payload resolves idempotently even at capacity; conflicting payloads cannot overwrite it. Private capture rechecks the current source instance/contentVersion. All reads precede transaction writes; UI state is updated outside retryable transaction callbacks. Offline/permission/quota/size failures keep the account's terminal tab result and expose honest recovery states.

Confirmed deletion removes summary and snapshot, decrements quota and changes its receipt atomically. A deleted receipt drops the payload fingerprint and contains no questions, answers or AI/key data. Receipts cannot be reset or deleted through the client. They prevent a stale draft or response-loss retry from recreating an intentionally deleted attempt. Full-attempt storage is bounded at 50; tiny anti-replay receipts grow with attempted/deleted archives and remain private. Deletion does not erase this disclosed marker. Saved quiz deletion/replacement is independent of archived history.

## Reading and release

Metadata queries use 20-item pages ordered by end time and attempt ID; statistics describe all bounded retained summaries, never only the visible page. Review uses the immutable snapshot, preserves the archived grade and labels changed/missing sources or unavailable images. It neither mutates current study state nor calls AI. Account generations discard late reads/saves from private UI after sign-out or owner changes; an already-submitted server transaction may finish only under its original owner.

The candidate policy must pass real demo-emulator SDK ownership, atomic pair/quota/receipt, UTF-8 size, conflict/response-loss, deleted-attempt retry and fiftieth-slot race cases. Keep configuration off until #79's reconciled baseline plus this change's complete policy/index candidate are published and verified. Roll back the client flag first, preserving private archives and compatible read policy. Production publication and designated-account persistence smoke require the repository's explicit release authorization.

The candidate release configuration is `firebase.history.json`, using the complete `firebase/firestore.history.indexes.json`: the #79 Console observation had no manual indexes/exemptions; this adds the custom-quiz questions exemption plus the history payload exemption. Re-read full production configuration and merge any intervening legitimate indexes/overrides before use. This candidate is not a deployment command or evidence of publication. Metadata uses descending endedAt with document ID in the same direction, covered by the observed default collection indexes; no filtered/group query or extra composite index is introduced. Emulator queries prove ordering/client behavior, not production index propagation.

Rules enforce owner access, envelope fields/types/UTF-8 bounds, the 50 counter and the four-document lifecycle. Detailed JSON/question/answer semantics are validated by the repository/domain boundary; Rules do not parse the opaque JSON or certify learning scores. On read the actual payload digest/schema/counts are checked before rendering. Server-confirmed quota revision changes may require a bounded fresh transaction when coupled Rules reject a stale contender; genuine unchanged permission denial is not retried as authorization.
